# Mods removed when building the DREAD server pack from the CurseForge client instance.
#
# DREAD publishes NO server pack (serverPackFileId = 0 in minecraftinstance.json), so the
# server is built from the client pack with this list subtracted. One filename per line;
# blank lines and `#` comments ignored. Matching is exact on the jar filename.
#
# How the list was derived — three signals, in order of authority:
#   itzg    the project slug appears in itzg/docker-minecraft-server's curated
#           globalExcludes (files/cf-exclude-include.json)
#   cmixin  the jar's mixin configs declare ONLY `client` mixins
#   ignsrv  mods.toml sets displayTest = IGNORE_SERVER_VERSION / IGNORE_ALL_VERSION
#
# A jar shipping its own data/<namespace>/ pack (recipes, loot, worldgen) is KEPT even when
# flagged — it is a content mod and the server needs it to generate and validate the world.
# That rule is what keeps ThisRocks (data ns `rocks`) on the server.
#
# Getting this wrong is cheap to correct in one direction and not the other: a client mod
# left in crashes the server at boot with the offending mod named in the log. A server mod
# removed by mistake shows up as missing content in a world that already generated. When in
# doubt this list KEEPS the mod.
